[[persistence-mapping]]
= 实体映射

通过 `infra.persistence.annotation` 包中的注解描述实体与表之间的映射：

[cols="1,1,4"]
|===
| 注解 | 目标 | 说明

| `@Table`
| 类型
| 指定实体对应的表名，如 `@Table(name = "t_user")`；缺省时按命名策略从类名推导。

| `@Id`
| 字段 / 方法
| 指定主键属性。

| `@GeneratedId`
| 字段 / 方法
| 声明生成型主键，默认由数据库生成，也支持 UUID、自定义生成器和组合注解，详见 <<persistence-id-generation>>。

| `@Column`
| 字段 / 方法
| 指定属性映射的列名；缺省时使用 `camelCase` 转下划线的策略。`value` 与 `name` 互为别名。

| `@Transient`
| 字段 / 方法
| 标记该属性不参与持久化。

| `@Version`
| 字段 / 方法
| 声明乐观锁版本属性，详见 xref:data-access/persistence/version.adoc[乐观锁]。

| `@EntityRef`
| 类型
| 声明该类型引用另一个实体的主表，用于没有自己的主键、而与目标实体共享主键的场景（如查询 / 更新模型）。

| `@UpdateBy`
| 字段 / 方法
| 标记用于更新的 `WHERE` 条件属性（不参与 `SET`）；当 `update()` 的实体没有可用主键时，由这些属性的值构成条件，详见 xref:data-access/persistence/entity-manager.adoc#persistence-update[更新]。

|===

== 默认命名策略

`DefaultEntityMetadataFactory` 的默认行为如下：

* **表名**：优先取 `@Table` 的值；否则使用类名，并将 `camelCase` 转为下划线、转为小写（`UserOrder` -> `user_order`）。
* **列名**：优先取 `@Column` 的值；否则将属性名 `camelCase` 转为下划线。
* **主键**：优先取标注了 `@Id` / `@GeneratedId` 的属性；否则取名为 `id` 的属性。一个实体只允许一个主键，否则抛出 `IllegalEntityException`。
* **属性过滤**：忽略名为 `class`、`new` 的属性、标注 `@Transient` 的属性以及内部类的 `this$0`。
* **混合类型**：通过 `TypeHandlerManager` 为每个属性解析 `TypeHandler` 完成 Java 类型与 SQL 类型的转换。

[[persistence-id-generation]]
== 主键生成策略

主键标识与主键生成是两个不同的职责：`@Id` 只标识主键，`@GeneratedId` 同时声明主键的生成方式。
`GenerationType` 与持久化生成器接口 `IdGenerator` 均位于 `infra.persistence` 包。

[cols="1,2,3"]
|===
| 方式 | 声明 | 行为

| 手动赋值
| `@Id`
| 调用方设置主键；是否写入该列仍由属性更新策略决定。

| 数据库自增
| `@GeneratedId` 或 `@GeneratedId(strategy = GenerationType.IDENTITY)`
| INSERT 排除主键列，执行后通过 JDBC generated keys 回填。

| UUID
| `@GeneratedId(strategy = GenerationType.UUID)`
| INSERT 前生成 UUID v7，支持 `UUID` 或 `String` 属性；字符串为标准带连字符格式。

| 自定义生成器
| `@GeneratedId(generator = OrderIdGenerator.class)` 或 `@GeneratedId(generatorName = "orderIdGenerator")`
| INSERT 前调用生成器，校验返回值类型并回填实体。
|===

[source,java,indent=0,subs="verbatim,quotes"]
----
@Table("t_user")
class User {

  @GeneratedId
  Long id;

  String name;
}

@Table("t_document")
class Document {

  @GeneratedId(strategy = GenerationType.UUID)
  String id;

  String title;
}
----

UUID 与自定义生成器仅在主键为 `null` 时执行，已有非空主键会保留。
`GenerationType.UUID` 固定采用 RFC 9562 UUID v7，包含 48 位 Unix 毫秒时间戳和 74 位安全随机数据。
其时间前缀有利于支持相应排序的数据库索引局部性，但不保证同毫秒内或跨节点严格递增；
时钟回拨会反映在时间戳中。生成时间可从 ID 中解析。
已有 v4 与新增 v7 可以共存。需要随机 UUID v4 或其他算法时，使用自定义 `IdGenerator`。
使用 `Long` 等包装类型表示尚未分配的数字主键；基本类型 `long` 的默认值 `0` 不为 `null`，不会触发应用生成器。
应用生成型主键始终参与 INSERT，不会被 `PropertyUpdateStrategy.notId()` 等普通属性策略排除。
数据库自增策略则始终排除主键列，因此不应对这种实体预先赋值主键。

=== 自定义生成器与依赖注入

实现 `infra.persistence.IdGenerator`，返回一个非空且可赋给主键属性的值。
框架负责将返回值设置到实体上，生成器无需直接修改主键属性：

[source,java,indent=0,subs="verbatim,quotes"]
----
import infra.persistence.EntityMetadata;
import infra.persistence.EntityProperty;
import infra.persistence.IdGenerator;

class OrderIdGenerator implements IdGenerator {

  private final OrderSequenceService sequenceService;

  OrderIdGenerator(OrderSequenceService sequenceService) {
    this.sequenceService = sequenceService;
  }

  @Override
  public Object generateId(Object entity, EntityMetadata metadata, EntityProperty idProperty) {
    return sequenceService.nextId();
  }
}

@Table("t_order")
class Order {

  @GeneratedId(generator = OrderIdGenerator.class)
  Long id;
}
----

上例的 `OrderSequenceService` 是应用提供的服务，其 `nextId()` 返回 `Long`。
框架按以下规则解析生成器：

* 仅指定 `generator`：优先使用容器中匹配该类型的 Bean；没有候选时通过构造器依赖注入创建实例。
  无法消除的多候选歧义会报错，可以使用 `@Primary` 或指定 Bean 名称。
* 仅指定 `generatorName`：按名称获取已有 `IdGenerator` Bean；找不到时直接报错，不创建替代实例。
* 同时指定 Class 与名称：按名称获取 Bean，并以 Class 约束其类型。
* 未指定自定义生成器：使用 `strategy`。指定自定义生成器时覆盖默认 `IDENTITY`，不能同时配置 `UUID`。

自动创建的生成器按 Class 在当前 EntityManager 内复用，并在 EntityManager 销毁时执行销毁回调。
按类型或名称查到的 Bean 按“生成器类型 + Bean 名称”在 Resolver 内缓存，后续解析复用首次获得的实例，
即使 Bean 声明为 prototype 也不会每次重新获取，因此生成器必须线程安全。
已有 Bean 不由 Resolver 销毁；自动创建的实例不会额外注册成容器单例。
通过容器创建的 `DefaultEntityManager` 会自动接收 BeanFactory；手动创建时，可以调用 `setBeanFactory(beanFactory)`
提供生成器的依赖，并在使用结束后调用 `destroy()` 释放自动创建的生成器。

=== 分布式 ID

`IdGenerator` 可以接入本地雪花算法、UUID v7、ULID、数据库号段、Redis 递增或远程 ID 服务。
当前内置策略为 `IDENTITY` 与 `UUID`（固定 v7），其他算法通过自定义生成器接入。
多节点唯一性、节点编号、时钟回拨处理和号段分配由生成器及其依赖服务负责。

对雪花或号段等有状态生成器，建议注册为线程安全的单例 Bean，通过名称引用：

[source,java,indent=0,subs="verbatim,quotes"]
----
@GeneratedId(generatorName = "distributedIdGenerator")
Long id;
----

这可以共享当前容器内的节点配置、序列状态或已领取号段。
不同应用实例仍需按所选算法配置跨节点协调机制。批量插入逐实体调用生成器；需要减少远程请求时，
可在生成器内部实现号段缓存。

=== Meta 注解与属性别名

`@GeneratedId` 可以作为 Meta 注解使用。框架通过合并注解解析声明，支持 `@AliasFor` 覆盖属性：

[source,java,indent=0,subs="verbatim,quotes"]
----
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

import infra.core.annotation.AliasFor;
import infra.persistence.annotation.GeneratedId;

@GeneratedId(generator = OrderIdGenerator.class)
@Retention(RetentionPolicy.RUNTIME)
@Target({ ElementType.ANNOTATION_TYPE, ElementType.FIELD, ElementType.METHOD })
@interface OrderId {

  @AliasFor(annotation = GeneratedId.class, attribute = "generatorName")
  String value() default "";
}

class OrderEntity {

  @OrderId
  Long id;
}

class SpecialOrderEntity {

  // 使用指定 Bean，并校验其类型为 OrderIdGenerator
  @OrderId("specialOrderIdGenerator")
  Long id;
}
----

组合注解本身已间接包含 `@Id`，无需再次标注。
生成时机、事务回滚和重试的说明见
xref:data-access/persistence/entity-manager.adoc#persistence-persist-id[主键与插入流程]。

[[persistence-ref-entity]]
== 引用实体 (@EntityRef)

标注 `@EntityRef` 的类型没有自己的表，而是复用被引用实体的主表与主键，常用于"只读查询视图"或"部分字段更新模型"：

[source,java,indent=0,subs="verbatim,quotes"]
----
@EntityRef(User.class)
class UserQuery {

  @Like
  String name;
}

// UserQuery 与 User 使用同一张表；UserQuery 未声明主键时，
// 其 ID 属性自动回退为 User 的 ID
----

框架为这类类型创建 `RefEntityMetadata`：

* `getTableName()` 复用被引用实体的表名。
* `findIdProperty()` 在自身未声明主键时回退到被引用实体的主键。
* `getRefMetadata()` 返回被引用实体的元数据（普通实体返回 `null`）。
* `getOrderSpec()` 在自身无声明式排序时回退到被引用实体的排序。

== 元数据

`EntityMetadataFactory#getEntityMetadata(Class)` 返回并缓存 `EntityMetadata`，其中包含表名、主键属性 / 列名、
版本属性、属性与列名的对应关系以及主键生成声明。元数据被视为只读，由工厂创建后缓存复用。
`getGeneratedId()` 返回合成后的 `@GeneratedId`（包含组合注解覆盖），无声明时返回 `null`；
`isAutoGeneratedId()` 仅表示数据库自增，不包含 UUID 或自定义应用生成器。生成器实例不保存在共享元数据中。

可以替换其中任意策略：

[source,java,indent=0,subs="verbatim,quotes"]
----
DefaultEntityMetadataFactory factory = new DefaultEntityMetadataFactory();

// 表名、列名、主键发现、属性过滤、类型处理器均可插拔
factory.setTableNameGenerator(new DefaultTableNameGenerator());
factory.setColumnNameDiscover(ColumnNameDiscover.forColumnAnnotation()
        .and(ColumnNameDiscover.camelCaseToUnderscore()));
factory.setIdPropertyDiscover(IdPropertyDiscover.forIdAnnotation()
        .and(IdPropertyDiscover.forPropertyName("id")));
factory.setPropertyFilter(PropertyFilter.filteredNames(Set.of("class", "new"))
        .and(PropertyFilter.forTransientAnnotation()));
----
