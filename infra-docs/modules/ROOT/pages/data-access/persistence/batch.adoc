[[persistence-batch]]
= 批量持久化

批量写入通过 `PersistenceProperties.maxBatchRecords` 控制：当累积的记录数达到该值时，
会隐式执行一次 `executeBatch()`；为 `0` 时不自动执行，由显式的刷新触发。

`BatchPersistListener` 会在每个批次执行前后收到通知，`BatchExecution` 暴露了 SQL 语句 `statement`、实体元数据
`entityMetadata`、更新策略 `strategy`、是否处理自增主键 `autoGenerateId` 以及当前批次收集到的实体集合 `entities`，
并通过 `getAffectedRows()` 返回该批次累计受影响的行数。监听器可通过 `@Order` / `Ordered` 排序。

== 主键生成与属性选择

批量插入为每个实体调用 `onPrePersist`，随后生成尚未赋值的应用主键，再绑定参数并加入 JDBC 批次。
自定义 `IdGenerator` 每个实体调用一次，不会自动合并成一次远程 ID 服务请求。
UUID 或自定义生成型主键始终包含在 INSERT 中；数据库自增主键在批次执行后尝试逐实体回填。

每个实体完成前置回调与主键生成后，再依据当前属性值和更新策略选择 INSERT 列。
实体类型、有序属性列表、更新策略和 JDBC 主键回填模式一致的记录复用 PreparedStatement；
仅在首次创建对应批次时生成 SQL。
不同列集合分别进入对应批次，不会因首个实体的空值状态而遗漏后续实体的属性。

批量与单条路径使用相同的注解优先规则：声明 `@GeneratedId` 时，数据库自增策略请求 JDBC 主键，
UUID 和自定义生成器不请求；未声明生成策略的模型也不请求。
数据库自增主键的批量返回能力和顺序取决于 JDBC 驱动。

批量操作通过 `RepositoryManager` 开启事务；事务回滚不会清除实体已经获得的应用主键。
重试及新实体判断见 xref:data-access/persistence/entity-manager.adoc#persistence-persist-id[主键与插入流程]。
