[[persistence]]
= 轻量级持久化框架 (Infra Persistence)
:page-section-summary-toc: 1

`infra-persistence` 在 xref:data-access/jdbc.adoc[JDBC] 抽象之上提供了一个轻量级的实体持久化层。
它不依赖 JPA/Hibernate，而是通过注解与运行时元数据把 Java 对象映射到关系表，并由
`EntityManager` 统一负责增删改查、示例查询、分页、乐观锁与生命周期事件。

== 主要功能一览

* xref:data-access/persistence.adoc#persistence-config[自动配置与依赖]：引入即用，无需编写样板代码。
* xref:data-access/persistence.adoc#persistence-mapping[实体映射]：注解驱动的表 / 列 / 主键 / 版本映射与可插拔的元数据工厂。
* xref:data-access/persistence.adoc#persistence-manager[`EntityManager`]：`persist` / `update` / `updateById` / `updateBy` / `saveOrUpdate` / `delete` / `truncate` / `find*` / `count` / `page` / `iterate` 等完整 API。
* xref:data-access/persistence.adoc#persistence-example[示例查询 (Query by Example)]：以对象作为查询条件，支持 `@Where`、`@Like`、`@OR`、`@OrderBy`。
* xref:data-access/persistence.adoc#persistence-update-strategy[属性更新策略]：精细控制哪些字段参与更新。
* xref:data-access/persistence.adoc#persistence-version[乐观锁]：基于 `@Version` 的并发控制。
* xref:data-access/persistence.adoc#persistence-paging[分页]：`Pageable` / `Page` / `Order`。
* xref:data-access/persistence.adoc#persistence-events[生命周期事件]：持久化前后的监听回调。
* xref:data-access/persistence.adoc#persistence-batch[批量持久化]：自动批处理与批次监听。
* xref:data-access/persistence.adoc#persistence-sql[SQL 构建与数据库平台]。

[[persistence-config]]
== 自动配置与依赖

在项目中引入 `infra-persistence`：

[source,groovy,indent=0,subs="verbatim,quotes"]
----
dependencies {
  implementation("cn.taketoday:infra-persistence")
}
----

该模块依赖 `infra-jdbc` 与 `infra-tx`，因此需要配置一个 `DataSource`（或 `RepositoryManager`）。
当容器中存在唯一的 `DataSource` 候选者时，`EntityManagerAutoConfiguration` 会自动注册以下 bean：

* `EntityManager`：默认实现为 `DefaultEntityManager`。
* `EntityMetadataFactory`：默认实现为 `DefaultEntityMetadataFactory`。
* `EntityEventRegistry`：默认实现为 `DefaultEntityEventRegistry`，并自动注册容器中所有的 `Listener` bean。
* `SqlStatementLogger`：SQL 日志记录器。

=== 配置属性

`PersistenceProperties` 绑定到 `persistence` 前缀：

[cols="1,1,1,3"]
|===
| 属性 | 类型 | 默认值 | 说明

| `persistence.max-batch-records`
| `int`
| `0`
| 单次批处理允许累积的记录数；达到该值后 `addToBatch()` 会隐式调用 `executeBatch()`。为 `0` 时不隐式执行批处理。

| `persistence.auto-generate-id`
| `boolean`
| `true`
| 是否自动回填由数据库生成的主键。

|===

=== 自定义

可以通过实现以下接口来定制自动配置的组件，它们会被自动收集并应用：

* `EntityManagerCustomizer`：定制 `DefaultEntityManager`（如更新策略、版本策略、默认分页等）。
* `EntityMetadataFactoryCustomizer`：定制 `DefaultEntityMetadataFactory`（如表名、列名、主键发现策略）。
* `TypeHandlerManagerCustomizer`：定制 JDBC 类型处理器（来自 `infra-jdbc`）。

[source,java,indent=0,subs="verbatim,quotes"]
----
@Component
class MyEntityManagerCustomizer implements EntityManagerCustomizer {

  @Override
  public void customize(DefaultEntityManager manager) {
    manager.setAutoGenerateId(false);
    manager.setDefaultPageable(Pageable.of(1, 20));
  }
}
----

[[persistence-mapping]]
== 实体映射

通过 `infra.persistence.annotation` 包中的注解描述实体与表之间的映射：

[cols="1,1,4"]
|===
| 注解 | 目标 | 说明

| `@Table`
| 类型
| 指定实体对应的表名，如 `@Table(name = "t_user")`；缺省时按命名策略从类名推导。

| `@Id`
| 字段 / 方法
| 指定主键属性。

| `@GeneratedId`
| 字段 / 方法
| 元注解形式的主键声明，表示主键由数据库生成（自增），配合 `autoGenerateId` 使用。

| `@Column`
| 字段 / 方法
| 指定属性映射的列名；缺省时使用 `camelCase` 转下划线的策略。

| `@Transient`
| 字段 / 方法
| 标记该属性不参与持久化。

| `@Version`
| 字段 / 方法
| 声明乐观锁版本属性，详见 <<persistence-version>>。

| `@EntityRef`
| 类型
| 声明该类型引用另一个实体的主表，用于没有自己的主键、而与目标实体共享主键的场景（如查询 / 更新模型）。

| `@UpdateBy`
| 字段 / 方法
| 标记用于更新的 `WHERE` 条件属性（不参与 `SET`）；当 `update()` 的实体没有可用主键时，由这些属性的值构成条件，详见 <<persistence-update>>。

|===

=== 默认命名策略

`DefaultEntityMetadataFactory` 的默认行为如下：

* **表名**：优先取 `@Table` 的值；否则使用类名，并将 `camelCase` 转为下划线、转为小写（`UserOrder` -> `user_order`）。
* **列名**：优先取 `@Column` 的值；否则将属性名 `camelCase` 转为下划线。
* **主键**：优先取标注了 `@Id` / `@GeneratedId` 的属性；否则取名为 `id` 的属性。一个实体只允许一个主键，否则抛出 `IllegalEntityException`。
* **属性过滤**：忽略名为 `class`、`new` 的属性、标注 `@Transient` 的属性以及内部类的 `this$0`。
* **混合类型**：通过 `TypeHandlerManager` 为每个属性解析 `TypeHandler` 完成 Java 类型与 SQL 类型的转换。

=== 元数据

`EntityMetadataFactory#getEntityMetadata(Class)` 返回并缓存 `EntityMetadata`，其中包含表名、主键属性 / 列名、
版本属性、属性与列名的对应关系以及主键是否为自动生成。元数据被视为只读，由工厂创建后缓存复用。

可以替换其中任意策略：

[source,java,indent=0,subs="verbatim,quotes"]
----
DefaultEntityMetadataFactory factory = new DefaultEntityMetadataFactory();

// 表名、列名、主键发现、属性过滤、类型处理器均可插拔
factory.setTableNameGenerator(new DefaultTableNameGenerator());
factory.setColumnNameDiscover(ColumnNameDiscover.forColumnAnnotation()
        .and(ColumnNameDiscover.camelCaseToUnderscore()));
factory.setIdPropertyDiscover(IdPropertyDiscover.forIdAnnotation()
        .and(IdPropertyDiscover.forPropertyName("id")));
factory.setPropertyFilter(PropertyFilter.filteredNames(Set.of("class", "new"))
        .and(PropertyFilter.forTransientAnnotation()));
----

[[persistence-manager]]
== EntityManager

`EntityManager` 是持久化的中心 API，所有方法在数据访问失败时抛出 `DataAccessException`，
实体元数据非法时抛出 `IllegalEntityException`。

=== 持久化

[source,java,indent=0,subs="verbatim,quotes"]
----
// 插入：支持单个实体、集合或 Stream；可指定更新策略与是否回填自增主键
int rows = entityManager.persist(user);
entityManager.persist(users);
entityManager.persist(user, PropertyUpdateStrategy.noneNull(), true);
entityManager.persist(userStream, true);
----

[[persistence-update]]
=== 更新

`update(Object)` 依据实体自身状态更新，可指定更新策略。条件选择顺序为：优先使用实体主键作为 `WHERE`；当实体没有可用主键时，
则使用标注了 `@UpdateBy` 的属性值构成 `WHERE` 条件（此时若没有任何 `@UpdateBy` 属性，会抛出 `InvalidDataAccessApiUsageException`）。

[source,java,indent=0,subs="verbatim,quotes"]
----
// 按实体状态更新（主键作为条件，或 @UpdateBy 属性作为条件），可指定更新策略
int rows = entityManager.update(user);
entityManager.update(user, PropertyUpdateStrategy.noneNull());

// 按主键更新
entityManager.updateById(user);
entityManager.updateById(user, 10L);
entityManager.updateById(user, PropertyUpdateStrategy.noneNull());
entityManager.updateById(user, 10L, PropertyUpdateStrategy.noneNull());

// 按指定属性（属性名或列名）的值作为 WHERE 条件更新
// 其余可更新属性由更新策略决定，例：UPDATE t_user SET ... WHERE name = ?
entityManager.updateBy(user, "name");
entityManager.updateBy(user, "name", PropertyUpdateStrategy.noneNull());

// 新实体插入、已存在则更新
entityManager.saveOrUpdate(user);
entityManager.saveOrUpdate(user, PropertyUpdateStrategy.noneNull());
----

当实体没有主键、又要以某个属性定位记录时，可在该属性上标注 `@UpdateBy`：

[source,java,indent=0,subs="verbatim,quotes"]
----
@Table(name = "t_user")
class User {

  @UpdateBy
  @Column(name = "name")
  String name;

  Integer age;
}

User user = new User();
user.name = "John";
user.age = 30;
entityManager.update(user);   // UPDATE t_user SET age = ? WHERE name = ?
----

=== 删除与清空

[source,java,indent=0,subs="verbatim,quotes"]
----
entityManager.delete(User.class, 1L);   // 按主键删除
entityManager.delete(example);          // 按实体 / 示例条件删除
entityManager.truncate(User.class);     // 清空整张表，保留表结构
----

=== 查询

[source,java,indent=0,subs="verbatim,quotes"]
----
// 按主键查询
User user = entityManager.findById(User.class, 1L);

// 首条 / 唯一结果，超过一条时抛异常
User first = entityManager.findFirst(User.class);
User unique = entityManager.findUnique(User.class, example);

// 列表查询：无条件、按排序、按示例、按 QueryStatement
List<User> all = entityManager.find(User.class);
List<User> sorted = entityManager.find(User.class, new Pair<>("age", Order.DESC));
List<User> matched = entityManager.find(example);

// 结果映射为 Map（按属性名或 keyMapper）
Map<Long, User> byId = entityManager.find(User.class, User::getId);

// 计数
Number total = entityManager.count(User.class);
Number active = entityManager.count(User.class, example);

// 分页
Page<User> page = entityManager.page(User.class, Pageable.of(1, 10));

// 迭代（避免一次性加载全部数据）
try (EntityIterator<User> it = entityManager.iterate(User.class)) {
  while (it.hasNext()) {
    process(it.next());
  }
}
entityManager.iterate(User.class, example, this::process);
----

[[persistence-example]]
== 示例查询 (Query by Example)

示例查询把对象的非空属性转换为 `WHERE` 条件。查询条件可以通过注解在属性上精细描述：

[cols="1,4"]
|===
| 注解 | 说明

| `@Where`
| 自定义条件片段或操作符，如 `@Where("status > ?")`、`@Where(operator = " > ")`；缺省为等值匹配。

| `@TrimWhere`
| 元注解形式，在生成条件前对字符串值执行 `trim()`。

| `@Like`
| 生成 `LIKE` 条件，默认会去除首尾空白。

| `@PrefixLike`
| 生成前缀匹配 `LIKE 'value%'`。

| `@SuffixLike`
| 生成后缀匹配 `LIKE '%value'`。

| `@OR`
| 将当前属性的条件与前一个条件以 `OR` 连接（默认为 `AND`）。

| `@OrderBy`
| 类级别指定完整 `ORDER BY` 子句；属性级别指定排序方向。

|===

例如，定义一个引用 `User` 主表的查询对象：

[source,java,indent=0,subs="verbatim,quotes"]
----
@EntityRef(User.class)
class UserQuery {

  @Like
  String name;              // name LIKE ?

  @PrefixLike
  String mobilePhone;       // mobile_phone LIKE ?

  @Where(operator = ">")
  Integer age;              // age > ?

  @OR
  @Where(operator = "<=")
  Integer score;            // ... OR score <= ?

  @OrderBy(direction = Order.DESC)
  @Column(name = "created_at")
  LocalDateTime createdAt;
}

UserQuery query = new UserQuery();
query.name = "Jo";
query.age = 18;
List<User> users = entityManager.find(User.class, query);
----

也可以直接使用 `Map` 作为条件（键为列名，值为参数）：

[source,java,indent=0,subs="verbatim,quotes"]
----
Map<String, Object> example = Map.of("name", "John", "age", 30);
List<User> users = entityManager.find(User.class, (Object) example);
----

=== 条件策略与值提取

* `PropertyConditionStrategy`：根据 `EntityProperty` 与值决定生成什么条件。内置实现包括
  `WhereAnnotationConditionStrategy`、`FuzzyQueryConditionStrategy`（`@Like` 系列）和
  `DefaultConditionStrategy`（默认等值）；自定义实现可通过 `InfraStrategies` 机制被发现，
  并排在上述默认实现之前生效。
* `ConditionPropertyExtractor`：在构造条件前对属性值做转换或包装，可通过
  `DefaultEntityManager#addConditionPropertyExtractor` 注册。

[[persistence-update-strategy]]
== 属性更新策略

`PropertyUpdateStrategy` 决定更新 / 持久化时哪些属性参与写入。它支持用 `and` / `or` 组合，
并内置常用策略：

[source,java,indent=0,subs="verbatim,quotes"]
----
PropertyUpdateStrategy.noneNull();        // 仅非 null 属性（默认）
PropertyUpdateStrategy.always();          // 全部属性
PropertyUpdateStrategy.never();           // 全部忽略
PropertyUpdateStrategy.notId();           // 排除主键
PropertyUpdateStrategy.isId();            // 仅主键
PropertyUpdateStrategy.isEqual(value);    // 值等于给定值
PropertyUpdateStrategy.isNotEqual(value); // 值不等于给定值

// 组合：非 null 且排除主键
PropertyUpdateStrategy strategy = PropertyUpdateStrategy.noneNull()
        .and(PropertyUpdateStrategy.notId());
entityManager.update(user, strategy);
----

[[persistence-version]]
== 乐观锁

在版本属性上标注 `@Version` 即可启用乐观锁。更新时框架会校验版本并自动递进；删除同样受版本约束。
每个实体只允许一个版本属性，否则抛出 `IllegalEntityException`。

开箱支持的类型：`int`/`Integer`、`long`/`Long`、`short`/`Short`，以及
`Instant`、`LocalDateTime`、`ZonedDateTime`、`OffsetDateTime`。数值类型递增，时间类型取当前时间。

[source,java,indent=0,subs="verbatim,quotes"]
----
@Table(name = "t_user")
class User {

  @GeneratedId
  Integer id;

  @Version
  Integer version;
}
----

自定义类型可实现 `VersionIncrementStrategy`，返回 `null` 表示不支持该类型以便回退：

[source,java,indent=0,subs="verbatim,quotes"]
----
entityManager.setVersionIncrementStrategy(current -> {
  if (current instanceof String v) {
    return v + "_updated";
  }
  return null; // 交给回退策略
});
----

[[persistence-paging]]
== 分页

`Pageable` 描述分页参数，`Page` 承载分页结果：

[source,java,indent=0,subs="verbatim,quotes"]
----
Pageable pageable = Pageable.of(2, 10);   // 页码从 1 开始
int offset = pageable.offset();

Page<User> page = entityManager.page(User.class, pageable);
List<User> rows = page.getRows();
Number totalRows = page.getTotalRows();
int totalPages = page.getTotalPages();
boolean hasNext = page.hasNextPage();
----

也可以通过 `DefaultEntityManager#setDefaultPageable` 设置缺省分页。排序使用 `Order.ASC` / `Order.DESC`，
配合 `Pair<String, Order>` 或 `Map<String, Order>` 使用。

[[persistence-events]]
== 生命周期事件

监听器通过泛型参数声明所关注的实体类型（无法解析泛型时监听所有实体），由 `EntityManager` 在操作期间
**同步**回调，因此监听器抛出的异常会传播给调用方。监听器可通过容器自动注册（作为 `Listener` bean），
也可手动注册到 `EntityEventRegistry`。

持久化 / 更新的回调会收到当次操作生效的 `PropertyUpdateStrategy`（决定哪些属性被写回，
默认 `noneNull()` 策略下仅非 null 属性参与写入），前置与后置回调拿到的是同一个策略实例。

[cols="1,3"]
|===
| 监听器 | 回调

| `PersistEventListener<T>`
| `onPrePersist(entity, metadata, strategy)` / `onPostPersist(entity, metadata, strategy)` / `onPersistFailed(entity, metadata, strategy, exception)`。回调可拿到选择写入属性的 `PropertyUpdateStrategy`；后置回调触发时自增主键已回填。

| `UpdateEventListener<T>`
| `onPreUpdate(entity, metadata, strategy)` / `onPostUpdate(entity, metadata, strategy)` / `onUpdateFailed(entity, metadata, strategy, exception)`。默认策略下只会写回非 null 属性，版本字段由框架覆盖；乐观锁失败也会触发失败回调。

| `DeleteEventListener<T>`
| `onPreDelete(entity, id, metadata)` / `onPostDelete(entity, id, metadata)` / `onDeleteFailed(entity, id, metadata, exception)`，可获取被删除实体与主键（按 id 或示例删除时二者可能为 `null`）。

| `PostLoadEventListener<T>`
| `onPostLoad`，实体从 `ResultSet` 装配完成后触发，可用于填充派生字段或写入缓存。

| `PostTruncateEventListener`
| `onPostTruncate`，清空表后触发（无实体实例，只有实体类与元数据）。

| `BatchPersistListener`
| `preProcessing` / `postProcessing`，见 <<persistence-batch>>。

|===

[source,java,indent=0,subs="verbatim,quotes"]
----
@Component
class UserAuditListener implements UpdateEventListener<User> {

  @Override
  public void onPreUpdate(User entity, EntityMetadata metadata, PropertyUpdateStrategy strategy) {
    // 校验或审计；strategy 决定哪些属性会被写回
  }

  @Override
  public void onPostUpdate(User entity, EntityMetadata metadata, PropertyUpdateStrategy strategy) {
    // 更新后处理
  }
}
----

[[persistence-batch]]
== 批量持久化

批量写入通过 `PersistenceProperties.maxBatchRecords` 控制：当累积的记录数达到该值时，
会隐式执行一次 `executeBatch()`；为 `0` 时不自动执行，由显式的刷新触发。

`BatchPersistListener` 会在每个批次执行前后收到通知，`BatchExecution` 暴露了 SQL 语句 `statement`、实体元数据
`entityMetadata`、更新策略 `strategy`、是否处理自增主键 `autoGenerateId` 以及当前批次收集到的实体集合 `entities`，
并通过 `getAffectedRows()` 返回该批次累计受影响的行数。监听器可通过 `@Order` / `Ordered` 排序。

[source,java,indent=0,subs="verbatim,quotes"]
----
class LoggingBatchListener implements BatchPersistListener {

  @Override
  public void preProcessing(BatchExecution execution, boolean implicitExecution) {
    // execution.statement, execution.entities
  }

  @Override
  public void postProcessing(BatchExecution execution, boolean implicitExecution, Throwable ex) {
    if (ex != null) {
      // 处理批次失败
    }
  }
}
----

[[persistence-sql]]
== SQL 构建与数据库平台

`infra.persistence.sql` 包提供了一组可复用的 SQL 片段构建器（移植自 Hibernate 的 SQL 支持），
包括 `Select` / `SimpleSelect` / `QuerySelect`、`Insert` / `InsertSelect`、`Update`、`Delete`、
`Restriction`（等值、比较、空值、逻辑组合等）、`JoinFragment` / `ANSIJoinFragment`、
`OrderByClause` / `MutableOrderByClause`、`CaseFragment` 等。

`QueryStatement` 定义了「渲染 SQL + 绑定参数」的契约：实现 `render` 返回
`StatementSequence`，`setParameter` 负责把值绑定到 `PreparedStatement`。`QueryCondition`
描述查询的条件部分：`collectRestrictions` 收集 WHERE 条件、`appendWhereClause` 将条件渲染到
缓冲区、`resolveOrderByClause` 解析排序、`setParameter` 绑定参数。内置实现有按主键查询、
无条件查询、示例查询与 `Map` 查询等。

`infra.persistence.platform.Platform` 抽象了数据库方言差异，默认实现为 `GenericPlatform`
（ANSI SQL）。可按需覆盖：

* `getForUpdateString()`：`FOR UPDATE` 片段。
* `getNoColumnsInsertString()`：无列插入的取值子句。
* `getTruncateTableStatement(String)`：清空表语句。
* `selectCountFrom(StringBuilder, String)`：计数语句。
* `createOuterJoinFragment()`：外连接片段。

[source,java,indent=0,subs="verbatim,quotes"]
----
Platform platform = Platform.generic();
----
