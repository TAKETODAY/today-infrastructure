[[mvc-test-server-setup-options]]
= 设置选择

MockMvc 可以通过两种方式之一进行设置。一种是直接指向你要测试的控制器，并以编程方式配置 Web MVC 基础设施。第二种是指向包含 Web MVC 和控制器基础设施的 Infra 配置。

要设置 MockMvc 以测试特定控制器，请使用以下代码：

[source,java,indent=0,subs="verbatim,quotes",role="primary"]
----
class MyWebTests {

  MockMvc mockMvc;

  @BeforeEach
  void setup() {
    this.mockMvc = MockMvcBuilders.standaloneSetup(new AccountController()).build();
  }

  // ...

}
----

或者，你也可以在通过 xref:testing/webtestclient.adoc#webtestclient-controller-config[WebTestClient] 进行测试时使用此设置，它委托给如上所示的同一个构建器。

要通过 Infra 配置设置 MockMvc，请使用以下代码：

[source,java,indent=0,subs="verbatim,quotes",role="primary"]
----
@JUnitWebConfig(locations = "my-servlet-context.xml")
class MyWebTests {

  MockMvc mockMvc;

  @BeforeEach
  void setup(WebApplicationContext wac) {
    this.mockMvc = MockMvcBuilders.webAppContextSetup(wac).build();
  }

  // ...

}
----

或者，你也可以在通过 xref:testing/webtestclient.adoc#webtestclient-context-config[WebTestClient] 进行测试时使用此设置，它委托给如上所示的同一个构建器。



你应该使用哪种设置选项？

`webAppContextSetup` 使用测试已经加载的 Web 应用上下文，因此可以验证该上下文中的 MVC 配置。
TestContext 框架会缓存可复用的上下文。你也可以通过 Infra 配置将 mock 服务注入控制器，
让测试专注于 Web 层。以下示例使用 Mockito 声明了一个 mock 服务：

[source,xml,indent=0,subs="verbatim,quotes"]
----
<bean id="accountService" class="org.mockito.Mockito" factory-method="mock">
  <constructor-arg value="org.example.AccountService"/>
</bean>
----

然后，你可以将 mock 服务注入到测试中以设置并验证你的期望，如下例所示：

[source,java,indent=0,subs="verbatim,quotes",role="primary"]
----
@JUnitWebConfig(locations = "test-servlet-context.xml")
class AccountTests {

  @Autowired
  AccountService accountService;

  MockMvc mockMvc;

  @BeforeEach
  void setup(WebApplicationContext wac) {
    this.mockMvc = MockMvcBuilders.webAppContextSetup(wac).build();
  }

  // ...

}
----

`standaloneSetup` 适合聚焦测试一个或几个控制器：显式传入控制器和依赖，按需配置 MVC 组件，
而不加载应用的 MVC 配置。要验证通过 Web 应用上下文注册的全局 Advice、自定义参数解析器或消息转换器，
应当使用 `webAppContextSetup` 并加载包含这些组件的配置；独立测试通过并不能证明这些组件已正确注册。

[[mvc-test-mockmvctester]]
== 使用 MockMvcTester 编写 AssertJ 断言

`MockMvcTester` 使用同一套 MockMvc 请求处理机制，提供 AssertJ 风格的断言。以下独立测试验证控制器的响应状态和文本：

[source,java]
----
import org.junit.jupiter.api.Test;

import infra.test.web.mock.assertj.MockMvcTester;
import infra.web.annotation.GET;
import infra.web.annotation.RestController;

import static org.assertj.core.api.Assertions.assertThat;

class GreetingTests {

  private final MockMvcTester mvc = MockMvcTester.of(new GreetingController());

  @Test
  void greeting() {
    assertThat(mvc.get().uri("/greet"))
        .hasStatusOk()
        .hasBodyTextEqualTo("Hello");
  }

  @RestController
  static class GreetingController {

    @GET("/greet")
    public String greet() {
      return "Hello";
    }
  }
}
----

在已加载 Web 应用上下文的测试中，用 `MockMvcTester.from(wac)` 验证 MVC 配置。
如果已经构建了带自定义设置的 `MockMvc`，可以用 `MockMvcTester.create(mockMvc)` 复用它。
