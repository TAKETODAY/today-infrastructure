= 混合使用组件类、XML 和 Groovy 脚本

有时可能希望混合使用组件类（通常是 `@Configuration` 类）、XML 配置文件或 Groovy 脚本来为测试配置 `ApplicationContext`。例如，如果因历史原因在生产中使用 XML 配置，你可能希望使用 `@Configuration` 类来为测试配置特定的 Infra 管理组件，反之亦然。

某些扩展框架可以支持同时从不同类型的资源（例如，`@Configuration` 类、XML 配置文件和 Groovy 脚本）加载 `ApplicationContext`。TODAY Framework 在 `infra-test` 模块中提供的大多数 `SmartContextLoader` 实现，每个测试上下文仅支持一种资源类型，但这并不意味着不能混合使用不同的配置形式。目标框架未提供 Spring 的 Groovy 专用测试上下文加载器，使用 Groovy 脚本时需要选择支持该资源类型的加载器。扩展框架也可以选择通过 `@ContextConfiguration` 支持同时声明 `classes` 和 `locations`；对于 TestContext 框架的标准测试支持，可以使用以下方式。

如果希望使用 `@Configuration` 类和资源位置（例如 XML 或 Groovy）来配置测试，必须选择其中一种作为入口，并由它导入或包含另一种。例如，在 `@Configuration` 类中，可以使用 `@ImportResource` 导入 XML 配置文件或由适当读取器支持的 Groovy 脚本；而在 XML 或 Groovy 脚本中，可以通过组件扫描或将其定义为普通 Infra Bean 来包含 `@Configuration` 类。这在语义上等同于生产配置：定义一组 `@Configuration` 类或一组 XML、Groovy 资源位置来加载生产 `ApplicationContext`，同时仍可导入或包含另一种配置。
