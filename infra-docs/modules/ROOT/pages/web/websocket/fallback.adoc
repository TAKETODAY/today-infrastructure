[[websocket-fallback]]
= 回退

在公共互联网上，限制性代理可能会阻止 WebSocket 交互，要么是因为它们未配置为传递 `Upgrade` 标头，要么是因为它们关闭看起来处于空闲状态的长连接。

解决此问题的方法是 WebSocket 模拟 -- 即首先尝试使用 WebSocket，然后退回到模拟 WebSocket 交互并公开相同应用级别 API 的基于 HTTP 的技术。

当前框架的 `WebSocketHandlerRegistry` 不提供 SockJS 注册 API，也没有内置的 SockJS HTTP 传输实现。
如需长轮询或其他 HTTP 回退方案，需要由应用自行实现或集成其他服务；不能仅通过配置 WebSocket 处理器启用。

[[websocket-fallback-cors]]
== CORS

WebSocket 握手的来源检查参见 xref:web/websocket/server.adoc#websocket-server-allowed-origins[允许的来源]。
它不会为应用自行实现的 HTTP 回退端点配置 CORS；这些端点需要单独使用
xref:web/webmvc-cors.adoc[Web MVC CORS 支持]，并按实际使用的来源、方法、请求头和凭据需求配置策略。
