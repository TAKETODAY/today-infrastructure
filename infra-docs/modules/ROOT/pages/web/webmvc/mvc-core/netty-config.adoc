[[mvc-container-config]]
= Netty 配置

`infra-web-netty-server` 模块提供了基于 Netty 的嵌入式 Web 服务器实现。
它可以通过 `infra-starter-netty-server` 启动器自动配置，也可以通过直接使用 `NettyWebServerFactory` 进行编程式配置。

== 依赖引入

要使用 Netty 作为嵌入式容器，您需要添加 `infra-starter-netty-server` 依赖：

[source,groovy]
----
dependencies {
  implementation 'cn.taketoday:infra-starter-netty-server'
}
----

== 配置属性

您可以通过 `server.netty` 前缀的配置属性来定制 Netty 服务器的行为。
以下是一些常用的配置项：

|===
| 属性名 | 描述 | 默认值

| `server.netty.worker-threads`
| 用于处理 I/O 操作的工作线程数 (Child EventLoopGroup)。
| 核心数 * 2

| `server.netty.acceptor-threads`
| 用于接收连接的线程数 (Parent EventLoopGroup)。
| 1

| `server.netty.worker-pool-name`
| 工作线程池名称。
| 无

| `server.netty.acceptor-pool-name`
| 接收线程池名称。
| 无

| `server.netty.max-connection`
| 允许的最大连接数 (SOMAXCONN)。
| 系统默认值 (Windows: 200, 其他: 128)

| `server.netty.socket-channel`
| 用于接受连接的 `ServerChannel` 实现类。
| 平台默认 (NIO)

| `server.netty.max-content-length`
| 请求体的最大长度。超过此限制将返回错误。
| 100MB

| `server.netty.max-chunk-size`
| 最大分块大小。
| 8KB

| `server.netty.initial-buffer-size`
| HTTP 请求解码的初始缓冲区大小。
| 128B

| `server.netty.max-header-size`
| HTTP 头的最大大小。
| 8KB

| `server.netty.max-initial-line-length`
| HTTP 请求行（第一行）的最大长度。
| 4096

| `server.netty.logging-level`
| Netty 日志级别 (TRACE, DEBUG, INFO, WARN, ERROR)。配置后注册 LoggingHandler。
| 无

| `server.netty.validate-headers`
| 是否启用头验证，以防止请求/响应拆分攻击。
| true

| `server.netty.connection-timeout`
| 连接超时时间。
| 无

| `server.netty.leak-detection`
| 资源泄漏检测级别 (DISABLED, SIMPLE, ADVANCED, PARANOID)。
| DISABLED

| `server.netty.data-received-queue-capacity`
| 用于存储接收数据块的队列容量。
| 256

| `server.netty.auto-read`
| 是否自动从通道读取数据。
| true

| `server.netty.auto-ack-ping-frame`
| 是否自动确认 PING 帧。
| true

| `server.netty.auto-ack-settings-frame`
| 是否自动确认 SETTINGS 帧。
| true

| `server.netty.http2-graceful-shutdown-timeout`
| HTTP/2 连接的优雅关闭超时时间。
| 30s

| `server.netty.chunked-supported`
| 是否支持 `Transfer-Encoding: Chunked`。
| true

| `server.netty.allow-partial-chunks`
| 是否允许分块被拆分为多个消息。
| true

| `server.netty.allow-duplicate-content-lengths`
| 是否允许超过一个 `Content-Length` 头。
| false
|===

此外，还有一些通用的服务器配置属性，位于 `server` 前缀下：

|===
| 属性名 | 描述 | 默认值

| `server.port`
| 服务器 HTTP 端口。
| 8080

| `server.address`
| 服务器绑定的网络地址。
| 0.0.0.0 (所有接口)

| `server.use-virtual-threads`
| 是否使用虚拟线程处理 HTTP 请求 (Java 21+)。
| false

| `server.shutdown`
| 服务器支持的关闭类型 (IMMEDIATE, GRACEFUL)。
| GRACEFUL
|===

=== 在反向代理后处理转发头

转发头是框架与服务器共享的 Web 配置，统一由 `infra-web` 模块的 `WebProperties` 管理，使用 `web.forwarded-headers` 前缀：

|===
| 属性名 | 描述 | 默认值

| `web.forwarded-headers.strategy`
| 处理策略：`web-server`、`framework` 或 `none`。
| 未指定时，由服务器在支持的云平台推断为 `web-server`，其他环境不处理

| `web.forwarded-headers.naming`
| 转发头命名：`x-forwarded` 或 `rfc-7239`。
| `x-forwarded`

| `web.forwarded-headers.use-prefix`
| 是否使用 `X-Forwarded-Prefix`。
| `false`
|===

只有在应用流量来自可信 HTTP 代理、且应用实例只能从可信网络直接访问时，才应启用转发头支持。
在支持转发头的云平台运行时，框架会自动启用服务器处理策略；这建立在平台能够隔离应用实例的前提上。
如果部署平台不满足该前提，应将 `web.forwarded-headers.strategy` 显式设置为 `none`。

代理通常使用 `X-Forwarded-Host`、`X-Forwarded-Port`、`X-Forwarded-Proto`、`X-Forwarded-For`，
或者使用 https://www.rfc-editor.org/rfc/rfc7239[RFC 7239] 定义的 `Forwarded` 头。
首先确认代理、负载均衡器或云平台采用的命名方式；实际部署中 `X-Forwarded-*` 更常见。
启用支持后，应用生成的链接、HTTP 302 响应和 JSON、HTML 中的 URL 可以反映原始请求的信息。

Reactor Netty 支持由服务器直接处理转发头：

[configprops,yaml]
----
web:
  forwarded-headers:
    strategy: web-server
----

这种方式的具体行为由服务器实现决定。支持的云平台默认采用 `web-server`，其他环境默认忽略转发头。
如需使用 RFC 7239，将 `web.forwarded-headers.naming` 设置为 `rfc-7239`；默认值为 `x-forwarded`。

`X-Forwarded-Prefix` 表示代理转发请求前剥离的原始 URL 路径前缀。默认忽略此头；要启用它，可配置：

[configprops,yaml]
----
web:
  forwarded-headers:
    strategy: web-server
    naming: x-forwarded
    use-prefix: true
----

服务器原生处理仅允许对 `x-forwarded` 命名启用前缀；`rfc-7239` 与 `use-prefix: true` 的组合会被拒绝。

如果不能使用服务器原生支持，可设置 `strategy: framework`。
MVC 使用 `infra.web.filter.ForwardedHeaderFilter`，响应式应用使用
`infra.web.reactive.server.ForwardedHeaderTransformer`，同样通过上述 `naming` 和 `use-prefix` 配置。
独立 Netty 服务器与 Reactor Netty 是不同的实现，当前请为独立 Netty 显式选择 `framework` 或 `none`，不要依赖云平台推断的原生处理。
可用时优先选择 `web-server`，避免通用框架处理的额外层次。

旧的 `server.forward-headers-strategy` 配置已由 `web.forwarded-headers.strategy` 替代，
原值 `native` 应改为 `web-server`。不提供 `server.request.header.forwarded.*` 配置。
原 `web.forwarded-headers.header-format` 改为 `web.forwarded-headers.naming`，其中 `standard` 改为 `rfc-7239`；
原 `web.forwarded-headers.use-forwarded-prefix` 改为 `web.forwarded-headers.use-prefix`。

=== 线程池配置

您可以自定义工作线程和接收线程的名称：

[configprops,yaml]
----
server:
  netty:
    worker-pool-name: "infra-netty-worker"
    acceptor-pool-name: "infra-netty-acceptor"
----

=== HTTP 请求执行器配置

Netty I/O 工作线程会将请求处理任务（如数据库访问、远程服务调用等阻塞逻辑）委托给 `HttpRequestExecutor` 执行，
从而避免阻塞高吞吐的 I/O 线程。框架内置两种实现：

* `SimpleHttpRequestExecutor`：委托给一个 `Executor`（默认线程池），适用于平台线程模式
* `VirtualThreadHttpRequestExecutor`：基于虚拟线程（Java 21+），适用于 I/O 密集型应用

使用 `server.use-virtual-threads` 即可切换为虚拟线程实现：

[configprops,yaml]
----
server:
  use-virtual-threads: true # 使用虚拟线程处理请求 (Java 21+)
----

在平台线程模式下，请求执行器优先复用 `applicationTaskExecutor` bean；当该 bean 不存在时，
才会使用 `server.netty.http-request-executor` 配置创建的默认线程池：

|===
| 属性名 | 描述 | 默认值

| `server.netty.http-request-executor.core-size`
| 核心线程数。
| 8

| `server.netty.http-request-executor.max-size`
| 最大线程数。队列排满时线程池可扩展至此大小。
| Integer.MAX_VALUE

| `server.netty.http-request-executor.queue-capacity`
| 队列容量。无界队列不会扩容线程池，此时 `max-size` 不生效。
| Integer.MAX_VALUE

| `server.netty.http-request-executor.allow-core-thread-time-out`
| 是否允许核心线程超时回收，启用后线程池可动态伸缩。
| true

| `server.netty.http-request-executor.keep-alive`
| 空闲线程存活时间。
| 60s

| `server.netty.http-request-executor.thread-name-prefix`
| 新创建线程的名称前缀。
| task-
|===

[configprops,yaml]
----
server:
  netty:
    http-request-executor:
      core-size: 16
      max-size: 64
      queue-capacity: 1024
      allow-core-thread-time-out: true
      keep-alive: 30s
      thread-name-prefix: "http-"
----

=== 优雅停机

Netty 服务器支持优雅停机，可以通过 `server.netty.shutdown` 配置相关参数。
优雅停机可确保在关闭服务器之前，不会提交新任务，但会允许正在进行的任务在“静默期”内完成。

|===
| 属性名 | 描述 | 默认值

| `server.netty.shutdown.quiet-period`
| 静默期（秒），在此期间如果没有新任务提交，则关闭。如果在此期间有任务提交，则静默期重新开始。
| 1s

| `server.netty.shutdown.timeout`
| 最大等待时间（秒），无论是否有任务提交，超过此时间强制关闭。
| 10s

| `server.netty.shutdown.unit`
| `quiet-period` 和 `timeout` 的时间单位。
| SECONDS
|===

[configprops,yaml]
----
server:
  netty:
    shutdown:
      quiet-period: 2 # 静默期（秒）
      timeout: 15     # 最大等待时间（秒）
      unit: SECONDS   # 时间单位
----

=== HTTP/2 配置

可以通过 `server.http2` 前缀配置 HTTP/2：

[configprops,yaml]
----
server:
  http2:
    enabled: true # 启用 HTTP/2
----

=== SSL 配置

可以通过 `server.ssl` 前缀配置 SSL：

[configprops,yaml]
----
server:
  ssl:
    enabled: true
    key-store: classpath:keystore.p12
    key-store-password: changeit
    key-store-type: PKCS12
    key-alias: tomcat
----

=== Multipart 配置

可以通过 `server.multipart` 前缀配置 Multipart 请求处理：

[configprops,yaml]
----
server:
  multipart:
    max-fields: 128
    max-header-size: 512B
    field-size-threshold: 16KB
    parsing-buffer-size: 4KB
    default-charset: UTF-8
    temp-base-dir: /tmp/uploads
----

== 编程式配置

如果您需要更细粒度的控制，可以注册一个 `WebServerFactoryCustomizer` bean 来定制 `NettyWebServerFactory`：

[source,java]
----
@Bean
public WebServerFactoryCustomizer<NettyWebServerFactory> nettyCustomizer() {
  return factory -> {
    factory.setPort(8088);
    factory.setWorkerThreadCount(10);
  };
}

@Bean
public ServerBootstrapCustomizer serverBootstrapCustomizer(){
  return bootstrap -> {
    bootstrap.option(ChannelOption.AUTO_READ, false);
  };
}

----

== 请求配置定制

您还可以通过 `NettyRequestConfigCustomizer` 定制请求配置：

[source,java]
----
@Bean
public NettyRequestConfigCustomizer requestConfigCustomizer() {
  return builder -> {
    builder.maxContentLength(DataSize.ofMegabytes(50).toBytes());
  };
}
----
