数据绑定会将不可信的输入绑定到应用对象。出于安全考虑，必须将输入严格限制在预期字段内。
本节介绍安全绑定的设计建议。

首先，Web 数据绑定应优先采用**不可变对象设计**。构造函数天然将绑定限制在预期输入范围内，
因此这种设计是安全的。可以使用 Java record 或具有主构造函数的类，两者都可以包含嵌套对象。
详情参见 xref:core/validation/beans-beans.adoc#beans-constructor-binding[构造函数绑定]。

另一种安全的选择是为预期输入设计**专用对象**。即使这些对象可变，
它们也能通过只暴露预期输入来约束绑定范围。

JPA 或 Hibernate 实体等领域对象通常不适合直接用于 Web 数据绑定，
因为它们包含的属性往往多于预期输入。对于这类对象，必须声明允许绑定的属性，例如：

[source,java,indent=0,subs="verbatim,quotes"]
----
@Controller
public class PersonController {

  @InitBinder
  void initBinder(WebDataBinder binder) {
    // 支持的模式语法参见 JavaDoc
    binder.setAllowedFields("firstName", "lastName", "*Address");
  }
}
----

NOTE: 也可以配置 `disallowedFields`，但排除列表容易遗漏字段，
并且容易随对象属性的演变而失效。目标 API 目前仍保留此配置，推荐优先使用明确的 `allowedFields`。

传给 `allowedFields` 和 `disallowedFields` 的模式并不限于顶层字段名。
它们是属性路径，使用与框架其他位置读写 bean 属性相同的语法，并支持 `*` 通配符。
因此，可以更精确地约束数据绑定：

* `"address"` 匹配 `address` 属性。
* `"person.address.city"` 匹配 `person` 的嵌套 `address` 属性中的 `city` 属性。
* `"addresses[0].city"` 匹配 `addresses` 数组或 `List` 中索引为 `0` 的元素的 `city` 属性。
* `"map[key]"` 匹配 `map` 属性中与 `key` 关联的条目。
* `"map*"` 匹配 `map` 属性中的每个条目，例如 `"map[key1]"` 和 `"map[key2]"`。
  相同的通配符语法也适用于数组或 `List` 中的索引元素。

有关支持的模式语法的更多信息，请参阅
{today-framework-api}/validation/DataBinder.html#setAllowedFields(java.lang.String...)[`DataBinder#setAllowedFields` JavaDoc]。

默认情况下，`DataBinder` 同时应用构造函数绑定和 setter 绑定。
对于不可变对象和专用对象，这通常没有问题；对于领域对象，则必须记得设置 `allowedFields`。
要确保数据绑定仅以显式声明预期输入的方式进行，可以在 `DataBinder` 上启用 `declarativeBinding`。
启用后仍会执行构造函数绑定，但只有配置了 `allowedFields` 才会执行 setter 绑定。
以下示例全局启用该标志，也可以通过 `ControllerAdvice` 的属性缩小适用范围：

[source,java,indent=0,subs="verbatim,quotes"]
----
@ControllerAdvice
public class ControllerConfig {

  @InitBinder
  void initBinder(WebDataBinder binder) {
    binder.setDeclarativeBinding(true);
  }
}
----
