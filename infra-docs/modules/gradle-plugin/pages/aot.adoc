[[aot]]
= 提前处理（AOT）
include::partial$attributes.adoc[]
Infra AOT 在构建时分析代码，并生成经过优化的代码。
它最常用于辅助生成 GraalVM 原生镜像。

Infra Gradle 插件内置对应用代码和测试代码执行 AOT 处理的支持，但默认不启用。
无需应用独立的 AOT 插件 ID；要在 JVM 应用中使用 AOT，请在应用 `cn.taketoday.application` 后显式启用：

[source,groovy,indent=0,subs="verbatim,attributes",role="primary"]
.Groovy
----
infraApplication {
  enableAheadOfTimeProcessing()
}
----

`enableAheadOfTimeProcessing()` 在项目配置阶段接入 AOT 源集和处理任务，重复调用不会重复注册。
启用后，AOT 输出会加入主源集和测试源集的运行时类路径，消费这些输出的运行、测试或打包任务可能触发 AOT 处理。
此配置不要求应用 GraalVM Native Image 插件；AOT 处理与运行时使用 AOT 初始化是不同的步骤。

应用 {nbt-gradle-plugin}[GraalVM Native Image 插件]后，会自动启用 AOT，无需再调用 `enableAheadOfTimeProcessing()`：

[[aot.processing-applications]]
== 处理应用
`processAot` 任务以标注了 `@InfraApplication` 的主类为基础，为运行时将注册的 bean 生成持久化表示，使 bean 的实例化尽可能直接。
还可以通过回调对 bean 工厂执行额外的后处理。
例如，这些回调用于生成必要的反射配置，以便 GraalVM 在原生镜像中初始化上下文。

由于 `BeanFactory` 在构建时就已准备就绪，条件也会在构建时求值。
这与常规 Infra 应用在运行时的行为有一项重要区别。
例如，如果要启用或禁用某些功能，就需要相应地配置构建时使用的环境。
为此，`processAot` 任务采用 {gradle-dsl}/org.gradle.api.tasks.JavaExec.html[`JavaExec`] 类型，可以按需配置环境变量、系统属性和参数。

GraalVM Native Image 插件的 `nativeCompile` 任务会自动配置为使用 `processAot` 任务的输出。


[[aot.processing-tests]]
== 处理测试
AOT 引擎可用于使用 Infra TestContext 框架的 JUnit 5 测试。
`processTestAot` 任务会处理符合条件的测试，生成 `ApplicationContextInitializer` 代码。
与应用的 AOT 处理一样，`BeanFactory` 会在构建时准备就绪。
与 `processAot` 一样，`processTestAot` 任务也是 `JavaExec` 的子类，可以按需配置，以调整处理过程。

GraalVM Native Image 插件的 `nativeTest` 任务会自动配置为使用 `processAot` 和 `processTestAot` 任务的输出。
