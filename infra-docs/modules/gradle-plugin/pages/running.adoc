[[running-your-application]]
= 使用 Gradle 运行应用
include::partial$attributes.adoc[]
要在不预先构建归档的情况下运行应用，请使用 `infraRun` 任务：

[source,bash,indent=0,subs="verbatim"]
----
./gradlew infraRun
----

`infraRun` 任务的类型为 {infra-run-javadoc}[`InfraRun`]，它是 `JavaExec` 的子类。
因此，Gradle 中用于执行 Java 进程的所有{gradle-dsl}/org.gradle.api.tasks.JavaExec.html[常规配置选项]都可用于该任务。
该任务会自动配置为使用主源集的运行时类路径。

默认情况下，插件会在主源集的输出中查找包含 `public static void main(String[])` 方法的类，并将其自动配置为主类。

也可以通过任务的 `mainClass` 属性显式配置主类：

.Groovy
----

----

或者，通过 Infra DSL 的 `mainClass` 属性为整个项目配置主类名称：

----

[[running-your-application.passing-arguments]]
== 向应用传递参数
与所有 `JavaExec` 任务一样，在 Gradle 4.9 及更高版本中，可以在命令行中使用 `--args='<arguments>'` 向 `infraRun` 传递参数。
例如，可以使用以下命令运行应用并激活名为 `dev` 的 profile（环境配置）：

[source,bash,indent=0,subs="verbatim"]
----
./gradlew infraRun --args='--infra.profiles.active=dev'
----

更多详情请参阅 {gradle-api}/org/gradle/api/tasks/JavaExec.html#setArgsString-java.lang.String-[`JavaExec.setArgsString` 的 Javadoc]。



[[running-your-application.passing-system-properties]]
== 向应用传递系统属性
由于 `infraRun` 是标准的 `JavaExec` 任务，因此可以在构建脚本中指定系统属性，将其传递给应用的 JVM。
要使系统属性的值可配置，可以通过{gradle-dsl}/org.gradle.api.Project.html#N14FE1[项目属性]设置它。
如果项目属性是可选的，请使用 `findProperty` 获取其值。
这样还可以通过 `?:` Elvis 运算符提供默认值，如下例所示：

[source,groovy,indent=0,subs="verbatim,attributes",role="primary"]
.Groovy
----
include::example$running/infra-run-system-property.gradle[tags=system-property]
----


上例将 `com.example.property` 系统属性设置为 `example` 项目属性的值。
如果未设置 `example` 项目属性，则系统属性的值为 `default`。

Gradle 支持多种设置项目属性的方式，包括在命令行中使用 `-P` 选项，如下例所示：

[source,bash,indent=0,subs="verbatim,attributes"]
----
./gradlew infraRun -Pexample=custom
----

上例将 `example` 项目属性的值设置为 `custom`。
随后，`infraRun` 会将此值用作 `com.example.property` 系统属性的值。

include::example$running/infra-run-source-resources.gradle[tags=source-resources]
----

这样可以在开发期间避免为了更新资源副本而重新执行资源处理任务。

资源修改能否在运行中的应用中立即生效，取决于应用读取资源的方式及其缓存策略。


[[running-your-application.using-a-test-main-class]]
== 使用测试主类
除 `infraRun` 外，插件还会注册 `infraTestRun` 任务。
与 `infraRun` 一样，`infraTestRun` 的类型也是 `InfraRun`，但它会从测试源集的输出中查找主类，而不是使用主源集中的主类。
它使用的也是测试源集的运行时类路径，而非主源集的运行时类路径。
由于 `infraTestRun` 的类型为 `InfraRun`，因此前面介绍的 `infraRun` 配置选项也都适用于 `infraTestRun`。
