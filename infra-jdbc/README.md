# TODAY JDBC

JDBC 基础设施模块，提供查询、参数绑定、结果映射和资源管理等能力。

## 单行查询性能基准

基准源码：[SelectBenchmark.java](src/jmh/java/infra/jdbc/SelectBenchmark.java)。以下记录为手写 JDBC 改用列索引读取后的本轮 JMH 结果，基准代码对应提交 `0fe4698059`，完整运行耗时为 **6 分 21 秒**。

### 测试场景与配置

- 使用 H2 内存数据库（MySQL 兼容模式），预先创建 1000 行固定随机种子生成的数据。
- 按主键循环查询一行，并映射为具有 13 个属性的 `Post`，覆盖时间字段和可空整数。
- 每个工作线程复用连接；每次调用创建并关闭 Statement，测量包含查询构造、参数绑定、执行和实体映射，不包含连接获取和初始化。
- 测量前校验全部 1000 行的所有 Bean 属性；禁用结果缓存，MyBatis 使用 Statement 级本地缓存。
- 手写 JDBC 基线按列索引（1–13）读取数据，保留 SQL NULL 和时间精度。
- JMH 使用 `AverageTime` 模式，单位为 `ns/op`；预热 5 轮、测量 5 轮，每轮 1 秒，3 个 fork，共 15 个测量样本。
- 本轮使用 Compiler Blackholes。具体 JDK/JVM 版本、JVM 参数、CPU 和操作系统版本未在本记录中提供，复测时应一并保存，并保持 Blackhole 模式一致。

参测依赖版本（见 [build.gradle](build.gradle)）：

| 实现                   | 版本  |
|------------------------|-------|
| Apache Commons DbUtils | 1.8.1 |
| sql2o                  | 1.6.0 |
| JDBI                   | 2.78  |
| MyBatis                | 3.5.9 |
| Bee / Honey            | 1.9.5 |
| jOOQ                   | 3.3.0 |

H2 的版本由项目依赖管理提供。这些结果描述上述参测版本，不代表各框架当前版本的性能。

### 本轮结果

### 结果解读

- 手写 JDBC 索引读取最快；TODAY 位置参数、位置参数加别名、普通命名参数路径占据第 2–4 名。
- TODAY 位置参数路径平均耗时约 **1.106 μs**，相对手写基线多约 **0.416 μs**。这是整个查询路径的差值，不能全部归为实体映射成本。
- TODAY 普通命名参数路径平均耗时约 **1.581 μs**，比本轮 DbUtils、sql2o Typical、JDBI、MyBatis 的均值分别低约 **8.6%、19.4%、22.0%、55.5%**。
- `Optimized` 方法名表示使用显式列和属性名别名 SQL，并不表示本轮测得的性能更优。TODAY 命名参数下该 SQL 比普通 SQL 多约 **1.909 μs**，而位置参数下仅多约 **0.065 μs**；sql2o 命名参数也出现类似增长。较长 SQL
  与命名参数处理路径的交互值得进一步分析，具体原因需要 profiler 验证。
- 上一轮按列名读取的手写 JDBC 为 **1374.749 ns/op**，本轮索引读取为 **689.409 ns/op**，均值降低约 **49.9%**。这是跨轮比较；精确评估列名与索引读取的差异，应将两种实现放在同一组基准中测量。

这些结论仅适用于本次 H2 内存数据库单行查询场景，不直接代表远程数据库、连接池获取、多行映射或应用端到端性能。

### 运行与分析

在仓库根目录运行模块 JMH 基准：

```bash
./gradlew :infra-jdbc:jmh
```

本轮结果输出位置为 `infra-jdbc/build/results/jmh/results.txt`。后续分析建议聚焦 `SelectBenchmark`，使用 JMH `-prof gc` 观察每次操作的分配字节数，并使用 CPU profiler 定位 SQL 解析、字符串处理、参数绑定和映射热点；通过相同投影下的
SQL 长度、命名参数与位置参数对照区分开销来源。
